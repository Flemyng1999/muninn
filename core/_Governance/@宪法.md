# 📜 知识管理宪法 v0.1.6

> 整个 KMS 的最高规范。任何执行人（人/AI）写入 vault / memory / 仓库文档前必须先读本文件。

---

## 0. 为什么存在本文件

解决三个真实问题（来自 2026-04-23 体检）：

- **双真相**：核心概念（ωL / S_k / p_W 等）在 memory 与 vault 并列叙述且不一致
- **零时效**：92 张卡 0% 带 `status / last_reviewed`，旧结论无法被机读识别并推翻
- **SSOT 真空**：核心概念无唯一主源，任何人/AI 都在重新定义

本宪法把规则从"执行人头脑里"转移到 vault 内可机读文件，使系统在换人/换 AI 后仍可运行。

---

## 1. 目标函数（North Star）

本 KMS 只优化两件事：

- **(a) AI 协作精度**：AI 做判断时能检索到唯一的、时效明确的知识源
- **(b) 自我接续性**：3 年后的你 / 换 AI 后，5 分钟内恢复任何 gate 的完整上下文

其他收益（美观、编号工整、全量链接网）不是目标，不得以它们的名义增加规则。

---

## 2. 适用范围（Scope v0.1）

试点阶段仅强制：

- **L0 Claude 行为层**：`~/.claude/projects/-Volumes-<ARBITER>-home-Code-<YOUR_PROJECT>/memory/`
- **L1 Wiki 层**：`vault/_Concepts/` + `vault/03-Zettelkasten/`
- **项目 scope**：仅 `<YOUR_PROJECT>`

**暂不强制**：其他 vault 子目录、其他项目、文献库（01-Literature）。试点期满后复审。

**v0.1.6 起新增强制**：`_Skills/` 作为 KMS 可复用工作流资产库纳入治理；其 lifecycle / usage / audit 由 R09 约束。

## 4. 第一性原理（Axioms）

> 条款可调，公理极少变更。修改公理 = 重写宪法。

### A 组：知识的本体论

| # | 公理 | 推论 |
|---|---|---|
| **A1** | 信息有生命周期（seedling → live → superseded/deprecated/retracted → archived） | 按"寿命"分层（L0–L3），不按"内容类型"分层 |
| **A2** | 每个事实只有一个源头（SSOT） | R01（唯一主卡）、R03（memory 瘦身） |
| **A3** | 写入成本 ≈ 检索成本 | 条款 ≤ 20；YAML 字段 ≤ 10 |
| **A4** | 知识的"新鲜度"必须可机读（`status / last_reviewed / supersedes`） | R02（YAML 元数据强制） |
| **A5** | AI 与人类共用同一套 wiki；memory 只放"行为规范 + 指针" | R03、R07 |

### B 组：治理的方法论

| # | 公理 | 推论 |
|---|---|---|
| **B1** | 按职责分角色，不按人/AI 分 | Author/Curator/Arbiter |
| **B2** | 规则必须在 vault 内，不在执行人头脑里 | 本 `_Governance/` 目录 |
| **B3** | 每个动作必须有机读触发条件（"看情况" = "没规则"） | `rules.yaml` 每条有 `trigger` |
| **B4** | 权限不对称：生成 ≠ 仲裁 | AI 永远不是 Arbiter |
| **B5** | 宪法本身是 evergreen 卡，也要被治理 | 季度复审 + CHANGELOG |

### C 组：管理学约束（来自体检数据）

| # | 公理 | 推论 |
|---|---|---|
| **C1** | 没有目标就没有评价标准 | North Star = (a) + (b)；所有规则可追溯到其一 |
| **C2** | 没有度量就没有改进 | `kms_health.sh` 周度运行 |
| **C3** | 合规成本 ≤ 违规代价 | 单人维护必须心理友好；高摩擦规则触发评审 |
| **C4** | 先度量后改造 | 本宪法基于 2026-04-23 体检起草 |

**冲突裁定顺序**：(a)+(b) 目标函数 > A1 生命周期优先 > Arbiter 决策（留痕 CHANGELOG）。

## 5. 三角色

角色按**职责**定义，不按"人/AI"身份。同一职责未来可由任何执行人承担（公理 B1）。

### 🖊️ Author — 产生原始素材
- 承担：<ARBITER>（思考）+ Claude（在用户指导下写草稿）
- 产出：log 条目、notebook 记录、升级候选草稿

### 🧭 Curator — 组织与升级
- 承担：Claude（提议 PR）+ <ARBITER>（merge）
- 产出：周度升级 PR、YAML 维护、孤儿卡挂接、断链修复

### ⚖️ Arbiter — 最终决策
- 承担：**仅 <ARBITER>**。**AI 永远不是 Arbiter。**
- 产出：merge PR、批准 supersede、修改 `_Governance/`、季度复审

### AI 的硬性限制（无论角色如何）

1. 不得直接写 `_Governance/` 任何文件（只能提议）
2. 不得未经 Arbiter 批准建主卡（`_Concepts/概念-*.md`）
3. 不得未经 Arbiter 批准改已存在主卡正文（typo / 断链除外）
4. 不得在 memory 新建 `project_*`（R03）
5. 不得单方面判定某卡 `superseded`

违反任一条 = 严重违规，体检仪表盘报警。

### 角色不是身份，是契约

即使 <ARBITER> 本人写 log，此刻扮演的是 Author，不能自动用 Arbiter 权限改主卡。**角色在每次动作时临时激活**，不是人的固有属性。

## 6. 核心条款速览

完整定义见 `rules.yaml`。铁律摘要：

| # | 条款 | 核心要求 |
|---|---|---|
| **R01** | SSOT 唯一主卡 | 项目 profile（`project_<name>.yaml`）列出的核心概念只能在 `_Concepts/概念-*.md` 有一张主卡；其他位置只许 `[[link]]` |
| **R02** | YAML 元数据强制 | 所有卡必须带 `id / type / status / scope / last_reviewed / created` |
| **R03** | Memory 瘦身 | Claude memory 只保留 `user_* / feedback_* / reference_* / pointer_*`；`project_*` 迁 vault |
| **R04** | 升级仪式 | 每日 log 末尾必须有"升级候选"区；每周五或 gate 变化时执行升级 PR |
| **R05** | 孤儿卡预防 | 新卡 72h 内必须挂到至少一个 MOC，否则保持 `status: seedling` |
| **R06** | 断链治理 | 许愿链接转 TODO；笔误周度修复；断链率 < 5% |
| **R07** | Narrative Spine 入 vault | 项目叙事骨架放 `02-Projects/`，不得仅在 memory |
| **R08** | 卡片生命周期治理 | status 6 值状态机（seedling/live/superseded/deprecated/retracted/archived）+ deprecation propagation（删卡/降级前扫描入链，PR 附报告）+ retraction banner + authoritative bit 同步转换 + **编辑深度矩阵（内容补丁 / 结构重构 / 定义治理，多档取最高）** + **卡片长期可理解性与证据卫生（去语境化 / 状态知识分离 / 证据强度 / agent 降噪）** |

> **R08 §8.8 卡片内容质量补充**：卡片正文记录长期知识，不记录短期工作状态；临时路线名、agent 过程语和未定义 verdict 应改写为长期可理解的机制、证据和边界。研究假设与误差容忍属于研究方法论问题，不作为本条治理法条。

## 7. 违规等级

由 `rules.yaml` 规定，共三档：

- **Block**：CI（`kms_health.sh`）报警并建议拒绝 merge（人工决策）
- **Warn**：周报告列出，Curator 下一次仪式时处理
- **Track**：仅记录，不干预

---

## 8. 宪法本身的治理

本宪法是 evergreen 卡，不是封存文档。

- 任何 `_Governance/` 修改必须经 Arbiter 批准，`CHANGELOG.md` 留痕
- **季度末** Arbiter 回答三问：(1) 过去 90 天哪条被违反？(2) 哪条从未触发？(3) 有没有规则没覆盖的新问题？
- `rules.yaml` 正文条款数 **≤ 20**；超过即设计失控，必须砍或合并
- **公理变更协议**：修改 A/B/C 任一条须 Arbiter 发起 + CHANGELOG 记录变更前后原文 + 评估下游条款连带影响

## 9. 快速上手（< 20 分钟）

换执行人/3 年后回来时按顺序读：

1. **本文件**（10 分钟）— 目的、公理、角色、条款速览
2. `rules.yaml`（浏览 5 分钟，使用时查阅）— 机读法条
3. `schemas/*.yaml`（写卡时查） — 卡片 YAML 规范
4. `project_<name>.yaml`（当项目相关） — 项目数据
5. `migration_v0.1.md`（当前迁移期）— 进度

移交场景：

- **换 AI**：新 AI 读本文件 + `rules.yaml`，默认角色 = Author + Curator（非 Arbiter）
- **换合作者**：默认角色 = Author；升级 Curator 需 Arbiter 授权；不存在第二个 Arbiter
- **3 年后 <ARBITER>**：自己是 Arbiter，读本节 + `CHANGELOG.md` 即可恢复
