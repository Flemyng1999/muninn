# 工作流-会议沉淀-规范落库

正式投喂入口：[[_Skills/02-Workflows/工作流-会议沉淀-规范落库-正式提示词]]

> [!abstract]- 适用场景
> 你把会议纪要、导师反馈、评审意见、临时讨论记录发给 AI，要求它**以 log 形式沉淀到当天 Journal**（不再单建会议页），并补全项目、文献、卡片之间的关联。
>
> **2026-04-24 变更**：`03-Meetings` 目录废弃；会议内容并入 `00-Journal/YYYY-MM/YYYY-MM-DD.md` 作为子节。

## 依赖读取顺序

1. 先读取 frontmatter 中的 `linked_role`、`required_blocks`、`related_templates`、`entry_prompt`。
2. 再读取当前正文中的会议沉淀规则与执行步骤。
3. 若要真正投喂模型，优先进入 `entry_prompt` 指向的正式提示词页。
4. 补齐方法依赖后，再去读取 `target_folders`、`scope_paths` 对应的业务文件。
5. 默认先读目标会议页、所属项目页和最关键的文献 / 卡片，不先全库扩散。

## 输入类型

1. 正式会议纪要。
2. 临时讨论记录。
3. 导师修改意见与反馈。
4. 评审建议、汇报反馈、决策结论。

## 核心规则

1. 按 [[_Templates/会议笔记模版]] 的结构写入：决策、修改意见、风险阻塞、待办、关联页面。
2. 优先把会议结论转成可执行任务，而不是保留为泛泛讨论。
3. 会议里提到的项目必须补双链。
4. 若会议直接影响项目推进，应同步更新对应项目页。
5. 会议中出现的长期知识只做识别与建议，必要时另行提炼为卡片，不把理论堆在会议页里。

## 执行步骤

1. 先从输入中识别会议主题、参与者、关键决策、修改意见、风险和待办。
2. 在当天 `00-Journal/YYYY-MM/YYYY-MM-DD.md` 追加会议子节（标题：`[HH:MM] ## 🗣 会议-<会议主题>`）。
3. 把零散讨论转为结构化结论，不直接贴原始聊天记录。
4. 补充和项目、文献、卡片之间最关键的双链。
5. 如会议内容已形成明确下一步，转成可执行待办。

## 输出

1. 生成或更新会议页。
2. 汇报本次新增的关键决策、待办和关联。
3. 如适合卡片化，指出建议沉淀的卡片主题。

## 成功标准

1. 会议页足够详细、规范、可复盘。
2. 会议结论可直接转化为行动，而不是停留在讨论层。
3. 会议记录不是孤岛，能从项目和相关知识页反查回来。

## 禁止事项

1. 不把会议页写成散乱聊天摘抄。
2. 不遗漏明确决策和待办。
3. 不忽略项目、文献、卡片之间的关联。
