# Repo/KMS 健康体检

> **类型**: workflow | **状态**: seedling
> **适用频率**: weekly 10min / monthly 30min / paper mainline pivot（事件驱动）
> **原则**: 路由优先 → 结构漂移 → 内容抽样 → 全量仅按需。禁止 broad filesystem search。禁止写治理文件。

## 概述

建立一个轻量、稳定、跨 AI 可执行的健康检查流程：任意 AI 在看到日历提醒或触发词后，都能按同一标准检查 repo 与 KMS 的连接、结构漂移、Skill 使用统计、paper 主线 pivot 风险，并输出可行动的体检报告，不越权修改治理层文件。

## 分层模型

| 层 | 检查内容 | 是否读 KMS 正文 | 频率 |
|---|---|---|---|
| L0 路由 | manuals 挂载 + Mac SSH + KMS marker 三文件 | 否，仅 marker 存在性 | 每次 |
| L1 结构 | repo INDEX、PROJECT.md/WORKING.md/KMS profile 一致性、git dirty | 否，仅 YAML + frontmatter | weekly + monthly |
| L2 内容抽样 | Skill metadata/trigger/dead-link/usage、proposal archive、paper 主线对齐 | 是，Skill frontmatter + usage markers | monthly |
| L3 全量审计 | L0–L2 全部 + R01–R08 健康指标 + concept card 抽样 | 是，穿透概念卡正文 | 仅用户显式触发 |

## L0 — 路由可达性（每次必跑）

```bash
cd <REPO_ROOT>
python3 scripts/check_ssot_views.py --check-ssh
```

断言：
- `/mnt/manuals/` 存在且 `AGENTS.md` + `reference/hosts.md` 可达
- `<MAC_HOSTNAME>` Tailscale IP 可从 hosts.md 解析
- SSH BatchMode 可通 Mac，KMS 三 marker 存在

若 L0 FAIL → 报告断裂点，不继续 L1+。

## L1 — 结构漂移（weekly + monthly）

```bash
git status --short
ls scripts/INDEX.md manuscripts/reviewer_reports/INDEX.md
```

检查项：
- `scripts/INDEX.md` 存在且列出当前活跃脚本
- `manuscripts/reviewer_reports/INDEX.md` 存在
- `PROJECT.md` 核心创新主张 / gate_status / 当前路线 是否与 KMS `project_<YOUR_PROJECT>.yaml` 的对应字段一致
- `WORKING.md` 是否指向合理的当前主线
- `docs/proposals/archive/` 文件数是否异常（>20 关注）

不检查：概念卡正文、journal 内容、notebook 代码质量。

## L2 — 内容抽样（monthly）

```bash
python3 scripts/kms_skill_audit.py --ssh auto --verbose
ls docs/proposals/archive/ | wc -l
```

抽样项：
- Skill metadata 对齐率、trigger 冲突、dead-link 数、triggerless live asset
- 近 30 天 usage marker 统计；seedling 零使用 30d+ → review candidate
- `docs/proposals/archive/` 最新 5 条是否已沉为 KMS card 或明确关闭
- paper 主线：最近 reviewer report 是否动摇了 active carrier / gate 判据 / paper 结构

## L3 — 全量审计（仅用户显式触发）

在 L0–L2 基础上增加：

```bash
bash scripts/kms_health.sh --verbose
```

额外检查：
- 全量 R01–R08 健康指标
- `_Concepts/` 概念主卡 `authoritative: true` 唯一性
- 月度 usage rollup 草稿建议

L3 输出建议但不执行任何 `_Governance/` 或 `_Concepts/` 写入。

## 禁止行为

- ❌ `find / -name` 或 `grep -r` 跨文件系统找 KMS/manuals
- ❌ 写 `_Governance/`、`_Concepts/概念-*.md`、`_Skills/`（除非 Arbiter 显式授权 + R09 scope）
- ❌ 将「检查 clean」写入 journal
- ❌ 维修变治理：不在 maintenance 窗口内做 supersede/deprecate/retract 决策
- ❌ 依赖默认时区：calendar 事件创建前必须 `date` + 显式 IANA timezone
