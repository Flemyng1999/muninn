# 工作流-流水记录-分流沉淀

正式投喂入口：[[_Skills/02-Workflows/工作流-流水记录-分流沉淀-正式提示词]]

> [!abstract]- 适用场景
> 你对 AI 口述刚发生的流水账，例如修了什么 bug、开发了什么功能、冒出了什么 idea、新增了哪些未来待办、买了什么以后要报账。目标是先分流，再决定要不要沉淀。

## 依赖读取顺序

1. 先读取 frontmatter 中的 `linked_role`、`required_blocks`、`entry_prompt`。
2. 再读取当前正文中的分流规则与执行步骤，不要只把它当成索引页。
3. 若要真正投喂模型，优先进入 `entry_prompt` 指向的正式提示词页。
4. 补齐方法依赖后，再去读取 `target_folders`、`scope_paths` 对应的业务文件。
5. 默认先读今日日记、未来任务池和强关联项目 / 卡片，不先全库搜索。

## 典型输入

1. 开发进展与 bug 修复经过。
2. 新功能、临时想法、实验观察。
3. 未来某天要做的待办。
4. 需要几天后处理的付款、报账、采购事项。

## 分流规则

1. 属于今天发生的上下文，记入今日日记的 `今日记录` 或 `Inbox`。
2. 明确不是今天做、但未来要做的事项，转入 [[02-Projects/@未来任务池]]。
3. 形成稳定方法、概念、踩坑经验、判断框架的内容，提炼为 03-Zettelkasten 卡片。
4. 已经进入持续推进的内容，补充到对应项目页并在 Journal 中保留当天痕迹。
5. 纯事务型记录如果只是暂存提醒，可先放 Journal，等晚间再统一分流。

## 执行步骤

1. 先按“今天记录 / 未来待办 / 长期知识 / 项目推进”四类切分输入。
2. 对每一类决定落点，不要只输出总结。
3. 如形成卡片，优先判断属于 `概念-`、`踩坑-`、`思考-`、`洞察-` 等哪一类。
4. 如产生未来待办，写成可执行动作，而不是口号。
5. 如涉及项目、文献、卡片，补全必要双链。

## 输出

1. 先说明哪些内容应进 Journal。
2. 再说明哪些应进未来任务池。
3. 若有长期价值，再给出建议沉淀的卡片方向或直接写卡片。

## 成功标准

1. 流水账被拆成可管理资产，而不是堆成一段聊天记录。
2. 待办、知识、项目进展三者边界清楚。

## 禁止事项

1. 不把所有流水都直接升格为卡片。
2. 不遗漏未来事务型待办，例如报账、采购、补材料。
3. 不把临时感想误记成正式结论。
