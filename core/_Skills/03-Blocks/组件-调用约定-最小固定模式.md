# 组件-调用约定-最小固定模式

> [!abstract]- 结论
> 最佳方式不是让 AI “学会整套 skills”，而是固定一套最小调用协议。对你现在这套 Obsidian 系统，最省力也最稳定的模式只有 3 段：`任务指令 + 技能入口 + 原始材料`。

## 最小固定模式

每次调用 AI 时，尽量只保留下面 3 段：

1. `任务指令`
2. `技能入口`
3. `原始材料`

推荐固定模板如下：

```markdown
请按这个 vault 中对应 skill 执行，不要只做摘要，要直接落库。

技能入口：[[对应的正式提示词页面]]

执行前请先阅读：
- 今日日记
- 相关项目页 / 文献页 / 卡片页
- 目标模板或目标文件

下面是本次原始材料：
[把你的会议记录 / 流水记录 / 文献记录贴在这里]
```

## 固定指令

为了减少心智负担，你平时真正需要重复输入的，其实只有这两句：

1. `请按对应 skill 执行，不要只做摘要，要直接落库。`
2. `执行前请先阅读相关上下文文件。`

剩下变化的部分只有：

1. 本次 skill 入口是哪一页。
2. 本次原始材料是什么。

## 最小上下文

如果当前 AI 能读取工作区，默认只给这 5 类：

1. `skill 文件`：本次要执行的正式提示词页。
2. `目标落点文件`：这次要修改或写入的目标文件。
3. `当前锚点文件`：通常是今日日记，保证 AI 知道“今天的上下文”。
4. `最关键关联文件`：只给 1 到 3 个最相关的项目页、文献页、卡片页。
5. `规则文件或模板文件`：只有当任务依赖明确格式时再补模板。

一句话记忆：

`1 个 skill + 1 个目标文件 + 1 个当天锚点 + 1 到 3 个关联文件 + 1 个模板`

## 文件与文件夹边界

1. 默认优先给文件，不优先给文件夹。
2. 只有在你也不知道关联对象具体是谁时，才让 AI 去局部目录里找。
3. 即便要扩展搜索，也优先给 `01-Literature`、`02-Projects`、`03-Zettelkasten` 这类局部目录，不先给整个 vault。

## 一个不容易出错的通用模板

```markdown
请按对应 skill 执行，不要只做摘要，要直接落库。

先阅读这些文件：
- [正式提示词页]
- [这次要改的目标文件]
- [今日日记或当天锚点文件]
- [最相关的项目页 / 文献页 / 卡片页]
- [目标模板，若需要]

如果这些文件不足以判断关联，你再去对应目录中补充搜索，不要先扫整个 vault。

下面是本次原始材料：
......
```

## 禁止事项

1. 不要每次重新发明 prompt。
2. 不要把“长期总说明”“正式提示词”“原始材料”混成一大坨。
3. 不要一开始就把整个 vault 交给 AI。
