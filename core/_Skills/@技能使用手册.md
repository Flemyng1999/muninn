# Skills 使用手册

> [!abstract]- 定位
> 这是 `_Skills` 的总使用手册。它不负责定义具体 skill 内容，而是回答“什么时候看哪一页、怎么把 skill 交给 AI、要给哪些上下文、AI 应该怎么沿 skill 依赖继续查找”。

## 边界（与 ~/.claude/ 的分工）

本目录仅放**对 vault 做什么**的工作流（早间启动 / 晚间结项 / 流水分流 / 会议沉淀 / 文献沉淀 / KMS 卡片起草与维护 / KMS 执行人角色）。

不放在这里的内容：

- **Claude Code 自身行为规范**（提问 SOP / 编码准则 / 不确定性处理）→ 在 `~/.claude/CLAUDE.md`
- **项目特定上下文**（gate 状态 / 路径约定 / 项目宪法引用）→ 在项目 `CLAUDE.md` 或 vault `_Governance/project_*.yaml`
- **领域知识定义**（核心概念主卡）→ 在 vault `_Concepts/`（被 R01 SSOT 强制约束）

判定法见 `~/.claude/CLAUDE.md` 顶部「工作流分工」节。两边只指针、不重复，标准就不模糊。

## 一句话结论

`_Skills` 不是让 AI 自动学会你的规则，而是让你每次都能用同一套方式，把 AI 切换到正确的工作模式。

## 场景 B：Claude Code 直接调用（推荐）

如果你在 Claude Code 中使用 Skills，不需要复制任何内容，直接告诉 Claude：

1. 要执行哪个 skill（文件路径）
2. 今日日记或锚点文件（文件路径）
3. 目标文件或关联文件（文件路径）
4. 原始材料（直接口述或粘贴）

示例：

```
按晚间结项 skill 执行，直接落库。

skill 文件：_Skills/02-Workflows/工作流-晚间结项-Git闭环-正式提示词.md
今日日记：00-Journal/2026-04-15.md

git diff 如下：
......
```

Claude 会自己读 skill 文件、沿 frontmatter 依赖链读取 workflow 和 block，然后直接修改 vault 文件落库。

## 场景 A：无文件访问权限时（ChatGPT / Copilot 等）

每次使用时，固定顺序如下：

1. 先看 [[_Skills/@技能库总览]] 找到本次任务属于哪一类。
2. 优先进入对应的”正式提示词”页，而不是先看说明页。
3. 复制正式提示词页 `# Role` 开始的全部正文内容。
4. 再补本次原始材料和最小必要上下文，粘贴给 AI。

## 最小调用模式

真正固定下来的模式只有 3 段：

1. 任务指令
2. skill 入口
3. 原始材料

可以直接套这个最小模板：

```markdown
请按对应 skill 执行，不要只做摘要，要直接落库。

技能入口：[[对应的正式提示词页面]]

执行前请先阅读：
- [今日日记或当天锚点]
- [目标文件]
- [最相关的项目页 / 文献页 / 卡片页]
- [模板页，若需要]

下面是本次原始材料：
......
```

## 什么时候给文件，什么时候给文件夹

默认优先给文件，不优先给文件夹。

### 应该直接给文件的时候

1. 你已经知道这次要改哪一页。
2. 你已经知道这次遵循哪条 skill。
3. 你已经知道最相关的项目、文献或卡片是谁。

### 只在这些情况给文件夹

1. 你自己也不知道关联对象具体是谁，要 AI 在局部范围里找。
2. 这次任务天然需要做关联发现，比如找对照文献。

即便如此，也优先给局部目录：

1. `01-Literature`
2. `03-Zettelkasten`
3. `02-Projects`

尽量不要一开始就说“看整个 vault”。

## 最小上下文清单

如果 AI 能读工作区，默认只给这 5 类上下文：

1. `skill 文件`
2. `目标落点文件`
3. `当天锚点文件`
4. `1 到 3 个最关键关联文件`
5. `模板文件`，仅在需要格式约束时给

你可以直接记成一句：

`1 个 skill + 1 个目标文件 + 1 个当天锚点 + 1 到 3 个关联文件 + 1 个模板`

## 哪些必须由你提供，哪些可以让 AI 自行补完

这是最重要的边界。

### 必须由你提供的

这些内容不要指望 AI 自己猜：

1. `本次任务属于哪一类`：至少要告诉它这是流水记录、会议沉淀、文献沉淀、早间启动还是晚间结项。
2. `原始材料`：会议纪要、流水记录、论文笔记、临时想法、报账事项，这些源输入必须由你提供。
3. `目标动作`：你是要它“直接落库改文件”，还是“先判断再执行”，这句必须明确说。
4. `当天锚点`：通常是今日日记。如果不点名，AI 很容易失去“今天上下文”。
5. `你已经知道的强关联对象`：比如明确属于哪个项目、哪篇文献、哪张卡片。你知道就应该直接给，不要让 AI 再猜一轮。

一句话说：

`任务类型、原始材料、执行意图、当天锚点、已知强关联` 这五类，默认由你提供。

### 可以让 AI 基于当前设计自行补完的

在你已经给出最小必要信息后，下面这些内容可以让 AI 先自己补：

1. `该读哪一份 role / workflow / prompt / block`：这是 `_Skills` 设计本身要解决的事。
2. `该按什么顺序读取 skill 依赖`：frontmatter 和正文里的“依赖读取顺序”已经定义好了。
3. `还需要补哪些模板文件`：如果 workflow 的 `related_templates` 已经明确，AI 应该自己去读。
4. `在局部范围内找哪些补充关联`：例如在 `01-Literature` 找对照文献、在 `03-Zettelkasten` 找相关卡片。
5. `该把内容落到 Journal、任务池、项目页还是卡片`：只要你给了原始材料和任务类型，这部分应由 AI 根据 skill 规则完成。

一句话说：

`方法依赖、模板依赖、局部关联发现、落库分流` 这些，应该由 AI 基于当前 skill 设计自行补完。

### 不应该让 AI 自己决定的

即使有 skills，也不要把这些决策完全放给 AI：

1. `这次到底要不要执行`：如果你自己都没决定是落库还是只讨论，AI 很容易走偏。
2. `整库搜索范围`：不要默认让 AI 扫整个 vault，应先给最小上下文。
3. `业务真实意图`：例如“这是正式结论还是临时想法”“这是明天要做还是以后再做”，如果你心里有明确判断，应该直接说。

## 最简单的分工公式

你只需要负责给出：

1. `我要做什么`
2. `原始材料是什么`
3. `今天上下文在哪`
4. `我已经知道它关联谁`

AI 负责补完：

1. `该调用哪条 skill`
2. `该顺着哪些依赖继续读`
3. `该按什么格式落库`
4. `在局部范围里补哪些关联`

## 一个实用判断标准

如果某条信息属于“只有你自己知道的真实意图”，就由你提供。

如果某条信息属于“skill 规则里本来就定义过的依赖或格式”，就应该让 AI 自己补完。

## AI 应该怎么沿 skill 继续查找

AI 不应该拿到一个 skill 文件后就扩散搜索整个 vault。

正确顺序是：

1. 先读当前文件的 frontmatter：
   - `entry_prompt`
   - `linked_role`
   - `linked_workflow`
   - `required_blocks`
   - `related_templates`
2. 再读当前正文中的“依赖读取顺序”和执行规则。
3. 方法依赖补齐后，再去读 `target_folders` 与 `scope_paths` 对应的业务文件。
4. 默认只读最小业务上下文，不先全库搜索。

## 什么时候看说明页，什么时候看正式提示词页

看说明页：

1. 你在设计 skill。
2. 你在检查这条 workflow 的边界。
3. 你想知道这个任务到底该怎么分流。

看正式提示词页：

1. 你已经确定要执行这条 skill。
2. 你准备把任务真正交给 AI。
3. 你希望 AI 直接改文件，而不是只讨论方案。

## 什么时候需要回写 _Skills

以下情况值得回写：

1. 某条 prompt 的执行顺序稳定有效。
2. 某种上下文清单反复证明足够用。
3. 某条技能依赖关系已经固定。
4. 某个禁止事项反复出现，值得正式写进规则。

以下情况不值得回写：

1. 一次性的聊天语气。
2. 某天临时有效、但没有复用价值的补充说明。
3. 只服务单次任务的具体业务内容。

## 最后记住一件事

不要追求“让 AI 自动懂整个系统”。

真正稳定的方法是：

1. 你负责选 skill。
2. `_Skills` 负责存规则。
3. AI 负责按当前上下文执行。
